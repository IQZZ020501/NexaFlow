## 顺序与边界

先完成文件检查和评测契约，再实现项目文件恢复；外部授权与长任务复用现有 MCP/工具授权。扩展包只公开实际稳定的可信契约。多主机调度沿用执行端口，不复制包含单例 Beat 的 `app` 容器。

每批改动完成后运行受影响的单元/集成测试、架构约束、静态检查和必要构建。执行镜像内验收使用独立标签和临时资源，保留用户现有服务。真实模型、连接器、Kata 和物理多主机结果分别记录；合同测试或普通 Docker 验证不能代替这些结果。

数据库改动使用递增 Alembic 迁移，验证空库升级及本批回退/重升。保留不可变历史和旧快照兼容。当前任务交付本地代码与可复现验证，未授权的推送、部署、外部发布和付费执行不在自动动作内。
